# M0 — Contracts, skeleton, and the smallest scan-to-order slice

Status: **BUILD** (authorized 2026-10-17). Branch: `impl/m0-scan-to-order`
(local-only; do not push or merge without separate authorization).
PR #1 (`planning/pack-review`) stays separate. Planning docs + ADRs
0001–0006 are architectural constraints, not starting points for redesign.

## First deliverable

A working end-to-end scan-to-order vertical slice, stateless:

image upload → AI extraction → Effect Schema validation →
interactive menu → bilingual order view.

No database, no auth, no admin, no discovery, no contributions in M0.
Persistence (OrderDraft, snapshots, revisions) lands in M2 per the roadmap.
M0 proves the slice works and measures the AI adapter honestly.

## Affected packages

| Package | M0 scope |
|---|---|
| `packages/contracts` | Effect Schema: string enums, `Money`, `MenuExtraction`. Single source of truth. |
| `apps/api` | Effect 4 backend. `MenuExtractionService` + one provisional provider adapter + one extract route. |
| `apps/customer` | TanStack Start. Upload → menu → bilingual order (one minimal flow). |
| Root | Bun workspaces + Turborepo + shared tsconfig + `.gitignore`. |

Explicitly **not** in M0: `apps/admin` (M3), `packages/domain`,
`packages/ui`, `packages/config` — add a shared package only when a real
second consumer needs it. No generic AI platform, no model router, no
fallback chain, no two-stage pipeline, no automatic menu merging.

## Adapter: one provisional provider

`MenuExtractionService` is implemented **once** against Effect's
`@effect/ai` `LanguageModel`. The provider is a `Layer` supplied at
runtime — swapping providers changes the layer, never the service.

- Provisional production layer: **GPT-6.1 Sol** (official OpenAI docs:
  $2 in / $0.10 cached / $2.50 cache writes / $10 out per 1M tokens;
  image input + structured outputs). Provisional, not selected.
- Evaluation runs reuse the same service with each shortlist layer:
  Gemini 3.8 Flash, GPT-6.1 Sol, Claude Sonnet 5.5, GPT-6 Luna,
  Gemini 4 Argon. Other candidates stay available for follow-up.

## Fixtures (evaluation, not demo data)

- 10–20 real Vietnamese menu photos (HCMC D1 / D3 / Bình Thạnh),
  user-provided, with manually verified gold labels. No scraped menus.
- Mix: typical menus + dense, difficult menus (glare, blur, multi-page,
  handwritten, mixed Vietnamese/English).
- Sessions, not isolated images: multi-photo menus evaluated as one
  complete scanning session.
- Decisive case: `Trà đào — Size M 35k / L 45k` — valid JSON with
  misassociated prices is a failure.

## Acceptance tests (must all pass for M0)

1. **Contracts.** Valid `MenuExtraction` decodes; malformed JSON, wrong
   types, or a price given as a bare string are rejected. Unknown /
   illegible values decode as `null` + an `uncertainty` entry, never as
   a guessed value. `Money` is integer minor units + currency code.
2. **Slice.** Upload a 2-photo menu → extraction → validated menu →
   interactive menu renders → bilingual order view shows original
   Vietnamese + translation. One happy path, no persistence.
3. **Association.** The `Trà đào` multi-price case associates M→35k and
   L→45k on the same item. Price–item–size misassociation is a severe
   failure, not a minor diff.
4. **Unknown preservation.** Illegible prices/options stay unknown with
   uncertainty recorded. A confident invention fails the run.
5. **Measurement.** Every evaluation run records actual input/output
   tokens (incl. reasoning), latency (p50/p95), retries, and cost per
   successful scan. Prior worked costs are estimates only.
6. **Traceability.** Each extracted item carries its source page
   (`pageIndex`) and, when visible, the original text (`sourceText`).
   Model confidence values and bounding boxes are never trusted
   without validation.
7. **Reliability.** Difficult cases are repeated; errors are reported
   with actual sample sizes. A small test set never implies a
   zero-error production guarantee.
8. **Boundaries.** Menus domain depends only on `MenuExtractionService`
   + contracts — no provider SDK imports. Domain vocab uses
   string-valued TS enums only; no inline string-literal unions, no
   numeric enums. No secrets in the repo (keys via env only).
9. **Checks.** `bun run check` (typecheck + lint + format) and
   `bun run test` pass. No push/merge without separate authorization.
